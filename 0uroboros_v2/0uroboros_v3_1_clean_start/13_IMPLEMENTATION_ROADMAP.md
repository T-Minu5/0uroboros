# Implementation Roadmap

Astra may reorder based on dependency evidence. This is an outcome roadmap, not a mandatory task script.

1. **Source/rules foundation** — inventory, canonical structures, deprecated placeholders excluded, starter deck correct, core tests.
2. **Core game state** — players, decks/hands/discards, Nodes, Locations, Servers, VP, probability, Actions, Wallet/Crypto, zones, server-authoritative randomness.
3. **Runtime loop** — three turns, Node opening, Actions, deployment, reveal, priority, effects, advancement.
4. **Wave Collapse** — Node 1-5 sequence, Location/card ordering, Power, winner/tie, Location Reward, Effect Bank, weighted selection, Circuit eligibility, game-ending stop.
5. **Draft** — Wallet, supply, purchases, Chaos, Circuit Reward, End Draft, next Cycle.
6. **Multi-cycle stability** — draw/discard/reshuffle, resets, stable barriers, no first-Cycle assumptions, browser smoke.
7. **Player-facing UX** — Node hierarchy, hand/deploy, inspect, target preview, Power/Location, Servers, probability, log, Draft, accessibility.
8. **LookDev / first-party identity** — board concept authority, Blender MCP board/table build where available, card art/icons, table/camera/material/lighting, card/Location objects, visual density/negative space.
9. **Effect language** — original reference-informed effects, local source-target storytelling, SVG/R3F/shader as appropriate, theatrical tiers, signature Collapse.
10. **Effect/content coverage** — coverage matrix, enough demo content for supported primitives/edges, Locations/Circuit Rewards, no rule invention.
11. **Demo hardening** — multi-cycle browser play, tests, performance, timing, errors/disconnects where in scope, benchmark review, launch instructions.

Stop before production-polish obsession for the human direction checkpoint.

## Publishing steps (after the direction checkpoint)

The repository is the authoring engine. Published products are built from it; nothing is forked.

12. **Seat-symmetric engine and authoritative server** — the engine exposes the same API to both seats (`view(seat)`, per-seat event redaction, injected clock); `packages/protocol` defines the wire schemas; `packages/server` owns the only `RuntimeSession` per table, drains the queue, runs timers and disconnect rules from `06_NETWORK_TIMERS_AND_FUTURE_SCOPE.md`, and records seed + command log for replay. Gate: `tests/game-server.test.ts` and the networked play gate in `14_TESTING_AND_ACCEPTANCE.md`.
13. **Shippable client** — `App.tsx` talks to the engine only through `GameClient` (`LocalClient` for offline practice, `OnlineClient` over WebSocket). The client build (`npm run build:client`) contains no Content Studio, LookDev tooling, agents or unreferenced art; `scripts/check-client-bundle.mjs` enforces it. Platform-specific concerns (auth, updates, store, input) sit behind a platform interface so the same client ships to web, Electron desktop (Windows/macOS, Steam) and later Capacitor iPad; the client stays touch-first and platform-neutral.
14. **Distribution and operations** — hosted server + CDN web client with email magic-link sign-in and a friends playtest first; then Electron packaging, code signing/notarisation, auto-update, Steamworks auth/achievements and steamcmd upload; then iPad with Sign in with Apple; then hardening (rate limits, matchmaking, error reporting, content pack rollout by content hash). Online PvP results feed Eco-Strat with `source: 'online-pvp'`.

## Asset folder authority

- `assets/card_art`, `assets/board`, `assets/materials`, `assets/models`, `assets/videos`, `assets/Icons`, `assets/HUDs` — shipping assets. Only files listed in `packages/content/art-manifest.json` (generated by `npm run assets:manifest`) are copied into the client build.
- `assets/library` — first-party art not currently referenced by any card, Location or board part. Studio-only; promote a file by referencing it from content and regenerating the manifest.
- `assets/source` — working files (`.blend`, review renders, superseded GLBs). Never shipped.
- `assets/reference` — concept and reference media (effect animations, interface references). Reference-only policy from `09_EFFECTS_AND_REFERENCE_POLICY.md` applies; never shipped.

`npm run assets:check` fails the build when a shipped asset is unoptimised or the manifest is stale.
